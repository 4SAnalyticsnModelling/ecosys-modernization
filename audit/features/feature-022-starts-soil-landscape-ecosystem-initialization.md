## Scope and provenance

Legacy source: `f77src/starts.f` (sha256 `21D67B83BBAC47D9D7B9D882E2088D7F489F2D89EFB9C4F780634434B3152635`). **Identity verified, not assumed from the filename**: header states "THIS SUBROUTINE INITIALIZES ALL SOIL AND ECOSYSTEM VARIABLES" (`:3`) -- broader than this pass's working hypothesis (soil physical/hydraulic state only). Actual scope: landscape elevation/slope/aspect geometry and topographic runoff gating; sky/leaf irradiance-interception angle tables; atmospheric/canopy air property unit conversions; soil-layer geometry, bulk density and solid-phase thermal properties; snowpack layer initialization; humus depth-partitioning; litter/residue/manure/POC/humus kinetic-fraction tables; the initial soil water/ice sentinel decode; SOM stoichiometry; the full microbial-biomass/residue/DOC/adsorbed-C,N,P initialization cascade; fertilizer-carryover and subsurface-boundary-gas array zeroing; and inter-cell distance/dispersivity geometry for solute flux. `startq.f` (`FEAT-021`, this pass's sibling) is the narrower per-PFT plant-state initializer; `starte.f` (`FEAT-008`) is soil chemistry/speciation. The three are siblings in the makefile's build order, not a clean domain split.

Called once per grid cell (`NX,NY`), with an outer elevation pass (`:267-359`) and a second pass (`:370-681`) for atmosphere/accumulator/canopy-layer state, followed by a per-cell, per-layer loop (`:698-1650`) for soil/snow/humus/microbial state. This dossier's central sentinel finding (below) confirms the task's premise that `starts.f`, not `starte.f`, carries the `THW`/`THI` magnitude-sentinel ladder described in this session's brief.

Zig: `ecosys-ng/src/stages/hourly_process_driver.zig`'s `topographicDownhillGate`, already found and tested by a prior pass (`audit/runs/run-001-ottawa-diagnostic-2026-09-18.md:46`, cross-referenced here rather than re-verified): `"topographicDownhillGate matches starts.f:274--303's four aspect quadrants exactly"` (`hourly_process_driver.zig:997`), and a second test confirms `IRCHG.EQ.0` unconditionally forbids export regardless of any other flow-favoring quantity (`:1019`). Disposition: `preserved`, already independently tested; not re-verified line-by-line this pass beyond confirming the citation is genuine.

### 4. Snowpack layer initialization -- `preserved`, thoroughly reconciled including a source-side dead accumulator

Zig: `ecosys-ng/src/soil/solute/snow_solute_transport.zig`'s `State.initializePhysicalState` is the explicit, self-disclosed production owner (`ecosys-ng/src/soil/water/snowpack_initial_state.zig:1-55` is the **unbound** duplicate, itself carrying a line-for-line reconciliation of every quantity against the bound owner). ### 5. Humus depth-partitioning, three-arm ladder (dryland/wetland/reconstructed) -- `preserved`

`starts.f:997-1085`: partitions humus into less-/more-resistant fractions (`FC1`/`CFOSC(1,4,..)`/`CFOSC(2,4,..)`) via a shape parameter `HCX` derived from accumulated humus depth (`TORGL`), with three structurally-parallel arms selected by `ISOILR` (natural soil) and a depth-vs-water-table test: dryland (`HCX=LOG(0.5)/TORGM`), wetland (`HCX=LOG(1.0)/TORGM`, i.e. `HCX=0`, no depth attenuation), and reconstructed soils (`FCX=1.0` fixed, no depth or wetland logic at all). Zig: `ecosys-ng/src/soil/biogeochemistry/humus_resistance_partition_initialization.zig`, self-described as "a faithful three-arm translation of `starts.f:997-1085`" (`:3`). Disposition: `preserved`. This is the "N parallel blocks" pattern the brief asked to check for; unlike `starte.f`'s `RC0P` outlier, all three arms here are confirmed faithfully carried, not silently dropped.

### 6. Initial soil water/ice content sentinel ladder (`THW`/`THI`) -- `preserved`; this is the ladder the task brief attributed to `starte.f`

`starts.f:1152-1177`: `THETW`/`THETI` are decoded from the soil file's `THW`/`THI` codes via a `>1.0` (saturation/porosity) / `==1.0` (field capacity/`FC`) / `==0.0` (wilting point/`WP`) / `<0.0` (near-zero, `1.0E-03` / exactly `0.0`) / else (direct value) five-way ladder, gated on `ISOIL(1,L)=ISOIL(2,L)=0` (both `FC` and `WP` supplied in the soil file). **Correction to this session's brief**: a direct grep of `starte.f` found no `THW`/`THI` references at all -- the sentinel-ladder pattern the brief described as `starte.f`'s is actually this file's. Zig: `ecosys-ng/src/soil/water/hydrology.zig`'s `decodeWaterFraction` (`:143-149`) and `ecosys-ng/src/soil/water/retention.zig`'s `resolve` (`:818-827`) both reproduce the identical five-way fork, already independently verified by `audit/issues/issue-024-top-layer-water-content-divergence-oracle-vs-zig.md`'s Experiment 1 (round 1), which traced both sides by hand for the Ottawa deck's layer 1 (`THW=1` for every layer) and confirmed both target the same `t=0` value (`0.28`, `FC(1)`). Disposition: `preserved`, refuted as the cause of `issue-024`'s still-open hour-1 divergence (that divergence is created during hour 1's process solve, not at this initialization step -- see `issue-024` for the live, unresolved follow-on question, which is out of scope for this dossier).

### 7. Litter/residue/manure kinetic-fraction codebook (`CFOSC`) -- `preserved`, confirmed correctly disambiguated from a same-shaped but numerically different sibling table in `hour1.f`

`starts.f:832-980`: an 11-branch `IXTYP(1,..)` ladder for surface litter type (maize/wheat/soybean/new-straw/old-straw/compost/green-manure/new-deciduous/new-coniferous/old-deciduous/old-coniferous, plus a default) and a 3-branch `IXTYP(2,..)` ladder for manure type (ruminant/non-ruminant/other), each filling the same `CFOSC(1..4,K,L,..)` protein/CH2O/cellulose/lignin table structure used elsewhere in the file. **Already-found and already-resolved divergence** (`ecosys-ng/src/management/organic_fertilizer_application.zig:63-74`): `hour1.f`'s own fertilizer-event litter-type codebook fills the identical `CFOSC` array shape from a *different* numeric code table, and disagrees with `starts.f`'s codes 4, 5 and 8 (swapped/different meanings) and lacks codes 9/10 entirely. Production is confirmed to read the correct codebook for each context (site-initialization vs. fertilizer-event) rather than conflating them. Disposition: `preserved`, confirmed both-directions per the contract's investigation order (this is exactly the kind of same-shaped-different-meaning trap the "N parallel blocks, 1 outlier" instruction was watching for, and it was already caught and fixed, not newly found this pass).
