## Scope and provenance
Legacy source/equations/interface and hashes: `f77src/watsub.f` (sha256 8606e2ea96e52ee8109cf0ef78b6b49abe0683e68baa41ffacbebaf1fe49da95), lines ~1637-1676 (unfrozen case) confirm the legacy matric-potential/water-content relationship is a **piecewise log-linear/log-power spline**, not van Genuchten, with four regimes keyed on water content `THETW`/`THETWR` relative to wilting point `WP`, field capacity `FC`, and porosity `POROS`:
  1. `THETW < WP`: `PSISM = max(PSISX, -exp(PSIMN + HCN*((WPL - ln THETW)/FCD * PSIMD)))` (dry-end extrapolation, floored at `PSISX`)
  2. `WP <= THETW < FC`: `PSISM = -exp(PSIMX + ((FCL - ln THETW)/FCD * PSIMD))` (log-linear between wilting point and field capacity)
  3. `FC <= THETW < POROS`: `PSISM = -exp(PSIMS + (max(0,(PSL - ln THETW)/PSD))^SRP * PSISD)` (log-power between field capacity and saturation; `SRP` is explicitly commented as "parameter for deviation from linear log-log water retention")
  4. `THETW >= POROS`: `THETW = POROS`, `PSISM = PSISE` (air-entry/saturation potential)
  Confirmed `grep`-negative: zero occurrences of "van Genuchten" or "Mualem" anywhere in `f77src/` -- this functional form is entirely absent from the legacy code; Mualem-van Genuchten is a wholesale replacement of the *hydraulic-conductivity* curve, layered next to (not instead of) a faithful reimplementation of the legacy retention curve (see below).

New source/equations/variant and hashes: `ecosys-ng/src/soil/water/retention.zig` (whole-file hash only available so far, via the tree-wide candidate-001 snapshot) contains **two coexisting retention representations**, confirmed by direct reading this session:

Function doc comments cite `hour1.f:2175--2178` (`legacyDryEndWaterFractionAtPotentialMpa`) directly and state `waterFractionAtPotentialMpa` is the "Exact inverse of the HOUR1 log-water branches," used because "NITRO evaluates this at PSIHY=-1.5e4 MPa to exclude hygroscopic water from active water." Primary reference and exact relevant section/equations: **confirmed 2026-09-19.** Van Genuchten, M. Th. (1980): "A Closed-form Equation for Predicting the Hydraulic Conductivity of Unsaturated Soils," *Soil Science Society of America Journal*, 44(5), 892-898, doi:10.2136/sssaj1980.03615995004400050002x -- confirmed via secondary sources (abstract/summary text; the full paywalled text was not fetched, so this is the "reliable secondary source confirming the standard closed form" the task allows, not a direct primary-text read) that the van Genuchten-Mualem relative-conductivity model has the closed form `K_r = Se^L * [1-(1-Se^(1/m))^m]^2`, where `L` is a pore-connectivity/tortuosity fitting exponent (conventionally `0.5`, per Mualem 1976). This is term-for-term identical to `retention.zig`'s `relativeHydraulicConductivityAtEffectiveSaturationAssumeValid` (`:206-230`): `saturation_to_inverse_m = Se^(1/m)`; `mualem_integral = 1-(1-saturation_to_inverse_m)^m`; `relative_conductivity = Se^pore_connectivity * mualem_integral^2`, with `pore_connectivity` defaulting to `0.5` (`:38`). The retention curve itself, `theta(h) = theta_r + (theta_s-theta_r)*[1+(alpha*|h|)^n]^-m` with `m=1-1/n` (`retention.zig:56-93`), is the standard original (non-Ippisch) van Genuchten (1980) form, which the module's own docstring already correctly self-identifies (`retention.zig:30-32`: "Original van Genuchten (1980) retention curve coupled to the Mualem conductivity model. This intentionally does not implement the Ippisch near-saturation modification."). No deviation found between the implemented equations and the standard closed forms; every constant, exponent, and sign checked term-for-term.

### Anchor-point invariant (2026-09-19, this session) -- tested, not merely read

The dossier's own flagged gap -- "the fitted Mualem-van Genuchten curve should reproduce the exact legacy field-capacity and wilting-point water contents at their exact pressure heads, since the fit is anchored through those points" -- is **already covered by an existing, passing test**, found by reading `src/validation/soil_water_retention_validation.zig` in full: test `"van Genuchten replaces a first-order joint with a second-order smooth curve"` (`:797-901`) builds the legacy-preserved `resolve()` curve for a real loam-like layer, fits a Mualem-van Genuchten curve anchored through that curve's own field-capacity and wilting-point fraction/pressure-head pairs via `fitOriginalMualemVanGenuchten`, and directly asserts (`:842-855`):
```
expectApproxEqAbs(field_capacity, fitted.parameters.waterContentAtPressureHead(field_capacity_head_m), 1.0e-9);
expectApproxEqAbs(resolved.curve.wilting_point_fraction, fitted.parameters.waterContentAtPressureHead(wilting_point_head_m), 1.0e-9);
```
This is exactly the invariant the dossier asked for -- evaluated against a real `resolve()`-derived legacy anchor (not a self-consistent constructed curve), at the exact anchor pressure heads. Ran this test directly this session under `zig test src/module_index.zig --test-filter "Genuchten"` (zig 0.16.0, matching the pinned `minimum_zig_version`): **passed**.

Also present, and additionally corroborating: `retention.zig`'s own `"runtime inflection fit recovers original Mualem van Genuchten parameters"` (`:911-941`) fits a curve from a *known* MVG parameter set's own field-capacity/wilting-point contents and checks the fitted `n`/`alpha`/`residual` match the known values to `1e-8`/`1e-9` -- an indirect form of the same invariant (exact parameter recovery implies exact anchor reproduction), also passed.

**A further, previously-unstated finding from reading the fit algebra itself (`retention.zig:566-614`, `evaluateRetentionFit`), not merely running the existing tests:** the two anchors are *not* symmetric in how exactly they are honored. `residual_water_content_m3_per_m3` is computed by algebraically isolating it from the equation `field_capacity_content = residual + (theta_s - residual) * Se_field` for *any* trial `n`:
```
residual_water_content = (field_capacity_water_content - saturated_water_content * Se_field) / (1 - Se_field)
```
Substituting this `residual` back into the standard retention formula at the field-capacity pressure head reproduces `field_capacity_water_content` **exactly, as an algebraic identity, for any `n` -- not merely to within Newton/Anderson solver tolerance.** The wilting-point anchor, by contrast, is the actual root-finding target: `n` is solved by driving `predicted_wilting_water_content - wilting_point_water_content_m3_per_m3` to zero via `numerics.newtonPicard`, so it is reproduced only to the solver's configured `water_content_absolute_tolerance_m3_per_m3`/`water_content_relative_tolerance` (defaults `1.0e-10`/`1.0e-8`), not exactly. This asymmetry is real, is a direct consequence of the fit's chosen parameterization (eliminate `residual` in closed form, solve only for `n`), and is benign (the field-capacity anchor's exactness is a bonus of the algebra, and the wilting-point anchor's tolerance is already tight relative to the layer's total water-content magnitude), but it means the dossier's original phrasing ("to solver tolerance" for both anchors) was imprecise: one anchor is exact by construction, the other is exact only to solver tolerance. No test was added for this specific asymmetry since the existing `1e-9`-tolerance test above already bounds both cases adequately; this is recorded as an analytical finding for precision, not a defect.

## Addendum 2026-09-18 (second session, ecosys-modernization-88): a real, narrow gap found in the legacy-preserved branch

`watsub.f:1660-1712`'s actual branch structure for the legacy-faithful curve is:
```
IF (BKVL(NUM,...) > ZEROS) THEN        [layer has real mineral bulk mass]
   normal FC/WP-based retention curve   [:1661-1676]
ELSEIF (DLYR(3,NUM,...) > DLYRM) THEN  [no mineral mass, layer still "exists" -- DLYRM=ZERO2 (`starts.f:95`), a near-zero existence guard, not a thin-layer threshold]
   ice-content-analog curve: FCX=FCI*THETIX, WPX=WPI*THETIX   [:1678-1702]
ELSE                                    [layer doesn't meaningfully exist]
   snap to saturation (POROS/PSISE)     [:1709-1712]
```
The middle branch substitutes an ice-content-derived retention curve for layers with **zero mineral bulk mass** (`BKVL<=0` -- pure organic/peat/ice-dominated material), not merely "thin" layers.

Searched `ecosys-ng/src/soil/water/retention.zig` for `WPI`/`FCI`/any ice-content-analog retention constant: **zero matches**. No `BKVL`-equivalent zero-bulk-density branch found there either. Confirmed this is a real, reachable case in ecosys-ng (not moot/dead-code): `ecosys-ng/src/soil/profile/initialization.zig:44-50` explicitly anticipates `bulk_density <= 0.0` for macropore-fraction purposes (`const macropore_fraction = if (bulk_density <= 0.0) 0.0 else profile.macropore_fraction[layer];`). Adjacent-but-not-matching: `thin_layer_pore_solute_reset.zig`/`thin_soil_boundary_solute_flux_reset.zig` handle degenerate-layer **solute** pore/flux state, a structurally different mechanism for a different physical quantity, not a confirmed counterpart for water-potential.

**Disposition: `unresolved`** on this narrow point (does not change the overall `preserved`/`replaced-by-approved-feature` disposition of the two main curves). Scope is narrow (zero-mineral-bulk-density layers only) and there is no evidence yet that it affects the current production frontier.

**Follow-up closed 2026-09-18 (same day, direct read of `resolve()`/`estimateFieldCapacity`/`estimateWiltingPoint`, `retention.zig:813-844`):** confirmed what `ResolvedCurve.waterPotentialMpa` actually does for a `bulk_density<=0` organic layer -- `resolve()` computes `field_capacity`/`wilting_point` via `estimateFieldCapacity`/`estimateWiltingPoint` (`:832-844`), which for organic soil (`organic_carbon_g_per_megagram >= organic_soil_threshold_g_per_megagram`) branch purely on `bulk_density_megagrams_per_m3` against two fixed thresholds (`organic_bulk_density_threshold_1/2_megagrams_per_m3` = 0.075/0.195 in `compatibilityParameters()`). A `bulk_density=0` layer falls into the lowest bracket and returns **fixed constants** `organic_field_capacity_1=0.27`, `organic_wilting_point_1=0.04` -- completely independent of the layer's *current ice content*. This is a **confirmed behavioral difference from the oracle**, not merely "no counterpart found": `watsub.f:1678-1702`'s `FCX=FCI*THETIX`/`WPX=WPI*THETIX` makes the retention anchors track the layer's live ice content, while `ecosys-ng` uses a static pair regardless of ice state. `waterPotentialMpa` itself does not error on this input (no explicit `bulk_density==0` guard anywhere in `resolve()`), so the curve silently runs with these static anchors rather than failing loudly or reproducing the ice-dependent legacy shape.

**Updated disposition: `unresolved` (confirmed, scoped) -- not `preserved`.** Impact assessment still pending: whether this ever matters depends on whether a real Ottawa-deck layer reaches `bulk_density<=0` during the run (has not been checked) and, if so, how far a static 0.27/0.04 anchor pair diverges from the ice-scaled legacy anchor at that layer's actual ice content. Recommend as a tracked, non-blocking G1 item: (a) check whether any layer in the production deck's actual soil profile ever has `bulk_density<=0`, (b) if so, quantify the anchor divergence at a representative ice content, (c) if material, port the ice-content scaling; if the deck never reaches this state, downgrade to a documented declared-limitation rather than a defect.
