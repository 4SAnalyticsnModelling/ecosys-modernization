# Issue 037 -- SOLUTE.F's restricted-domain (ISALTG=0 / static-salt) soil-layer NH4-NH3 and phosphate band-zone formulas are translated and unit-tested in Zig but have zero production callers

Status: **OPEN, needs a coordinator scope decision.** Not a numerical-correctness defect in the translated formulas themselves (those were verified faithful, including a deliberately-preserved legacy quirk); the gap is in production wiring/reachability.

Owner: found by this session's audit fork, 2026-09-19, while auditing FEAT-017's "restricted band-zone mirrors" assignment (`f77src/solute.f`, ISALTG=0 branch, soil layers).

## What was found

`f77src/solute.f` branches on `ISALTG` (`:589,2880,4203,4630`; comment at `:2880-2882`: "IF NO SALT IS SELECTED IN SITE FILE THEN A SUBSET OF SOIL EQUILIBRIA REACTIONS ARE SOLVED: MOSTLY THOSE FOR PHOSPHORUS AND CO-REACTANTS"). The `ISALTG.EQ.0` ("restricted"/static-salt) branch does **not** mirror the full-salt branch's carboxyl dissociation (`:1407-1423`) or Al(OH)/Fe(OH)/carbonate ion-pairing (`:1432-1568`, `RALO1..4`/`RHCO3`/`RCO2Q`) at all -- confirmed absent by a full-file grep; this is a real, by-design omission on the Fortran side, not a translation gap. It **does**, however, mirror cation exchange (`:3348-3520`, restricted counterpart of `:1210-1387`), phosphate anion exchange (`:3075-3139` non-band, `:3268-3307` band; restricted counterparts of `:957-1174`), and NH4-NH3 dissociation (`:3547-3588`, restricted counterpart of `:1461-1494`) -- each with formula differences from the full-salt branch (documented in `FEAT-017` Findings 4 and 6).

Zig has direct, unit-tested translations of these restricted-domain formulas:
- `ecosys-ng/src/soil/solute/aqueous_reaction_rates.zig` (sha256 `BC6E1581D8F1CC4EBC012919BF92BAA490CEA9ECCFCE13E5DAF13DD9E8811418`), `calculateRestrictedAmmoniumSourceOrder` (`:82-142`), explicit doc comment citing `SOLUTE.F lines 3557--3588`, with a dedicated test (`:441-472`, `"SOLUTE 3557-3588 restricted ammonium retains band XMIN dependency"`) that specifically exercises the retained-`XMIN` legacy quirk at line `:3578`.
- `ecosys-ng/src/soil/solute/phosphate_exchange.zig` (sha256 `02C87C082842D30211620F9A7FA74ADB46040D80A72F600B7A3A51555DE09504`), `calculateRestrictedSourceOrder` (`:61-134`, citing `SOLUTE.F :3075-3139`) and `calculateRestrictedBandSourceOrder` (`:139-`, citing `SOLUTE.F :3268-3307`, explicitly documenting the source's `FIONX`/`FIONN` mixing), each with its own test.

A whole-codebase grep (`grep -r "calculateRestrictedAmmoniumSourceOrder\|calculateRestrictedSourceOrder\|calculateRestrictedBandSourceOrder" ecosys-ng/src`) finds **no callers outside the two defining files and their own in-file tests.** Separately, the per-cell static/dynamic-salt configuration flag (`dynamic_salts` / `salinity_enabled_by_cell` / `SalinityChemistry`) is genuinely wired through many other subsystems -- snow-solute transport (`snow_solute_transport.zig`), tillage salt incorporation (`salt_incorporation.zig`, `surface_chemical_transfer.zig`), root salt uptake (`root_processes_uptake.zig`), fire/combustion salt release (`organic_matter_fire_exchange.zig`, `disturbance_management_dispatch.zig`), fertilizer-band amalgamation (`fertilizer_band_nitrate_phosphate.zig`), and litter's own carboxyl gate (`litter_reaction_rates.zig:770`, `if (context.dynamic_salts) try carboxylRate(...) else 0`) -- but **not** by the core soil reaction-chemistry production path (`reaction_solve.zig`, `reaction_try_network.zig`, `reaction_solver_*.zig`, `cation_exchange.zig`'s main `calculate`/`calculateSourceOrder`, `aqueous_reaction_rates.zig`'s main `calculate`, `phosphate_exchange.zig`'s main `calculateForZone`), none of which branch on the flag at all for soil layers.

The practical implication: a soil cell configured for static-salt chemistry (`ISALTG=0`) still receives the full-salt/dynamic cation-exchange, NH4-NH3, and phosphate-exchange formulas in production ecosys-ng today. The restricted-domain formulas exist and are individually correct (including a deliberately preserved legacy defect) but are dead code from the production model's perspective.

## Why this needs a record

This is adjacent to, but distinct from, the "unified-kernel deviation" pattern in `issue-018`/`issue-020`/`issue-021`/`issue-036`: those are cases where Zig runs a *different, unified* formula in place of a legacy variant. Here, Zig has the *matching* variant written and tested but **never invokes it** -- a reachability/wiring gap rather than a formula deviation. It was not caught by the existing FEAT-017 dossier because Finding 4's original pass verified formula fidelity (comparing Fortran text to Zig function bodies) without checking whether those Zig functions are called from any production stage.

## Disposition

`unresolved`, pending a coordinator decision: either (a) static-salt (`ISALTG=0`) soil-layer chemistry is out of the v1.0.0 production scope entirely (in which case these functions should be documented as intentionally-unwired reference translations, or removed/flagged dormant per contract's "dormant branches remain in the inventory" clause), or (b) it is in scope and the soil reaction-network stage needs to branch on the per-cell salinity flag the same way litter's `carboxylRate` already does. No production run this pass exercises `ISALTG=0` soil cells to observe actual impact; materiality is not evaluated.
