# Issue 042 -- `trnsfrs.f` subsurface macropore *boundary* discharge/recharge branch structure diverges from both its own micropore boundary treatment and the sibling gas file at the identical location

Status: OPEN
Owner: unassigned
Candidate/input hashes: `f77src/trnsfrs.f` sha256 `89F5D7CD44C0561E9B7233AD42164CBB1F9A6DF84BF90480A7A126177C34C5F1`; `f77src/trnsfr.f` sha256 `466E28F9A84BC67DB7998F213B48FD56312CC9C01DA09E59E6C36117637635EC`

## Confirmed content and location

This is a **different** location/mechanism from the already-filed `issue-029` (vertical macropore convective netting inside a soil layer, `trnsfrs.f:5431-5688`). This issue is about the **external subsurface macropore boundary flux** section (`trnsfrs.f:8059-8417`, banner "SUBSURFACE SOLUTE BOUNDARY FLUX THROUGH MACROPORES"), which sits between two structurally-comparable sections: the subsurface **micropore** boundary flux immediately above it (`trnsfrs.f:7711-8058`) and the sibling gas file's macropore boundary flux at the identical physical location (`trnsfr.f:6470-6564`).

**Micropore boundary (`trnsfrs.f:7735-8057`, symmetric reference form):**
- Discharge: `IF(NN.EQ.1.AND.FLWM(...).GT.0.0.OR.NN.EQ.2.AND.FLWM(...).LT.0.0)THEN` (`:7748-7749`) -- one combined condition covering **both** boundary sides (`NN=1` and `NN=2`), gated on the correct flux variable for this section (`FLWM`, the micropore water flux).
- Recharge: `ELSEIF((NN.EQ.2.AND.FLWM(...).GT.0.0).OR.(NN.EQ.1.AND.FLWM(...).LT.0.0))THEN` (`:7825-7826`) -- likewise one combined condition covering both sides.
- Every `NN`/sign combination is covered by exactly one of these two branches (both gates are mutually exclusive and jointly exhaustive given `ABS(VFLW)>ZERO` already required to enter this code), so both boundary sides get correctly classified as discharge or recharge regardless of `NN`.

**Sibling gas file's macropore boundary (`trnsfr.f:6484-6564`), same physical section:**
- Discharge: `IF(NN.EQ.1.AND.FLWHM(...).GT.0.0.OR.NN.EQ.2.AND.FLWHM(...).LT.0.0)THEN` (`:6500-6501`) -- one combined condition covering **both** sides, correctly gated on `FLWHM` (the macropore water flux, matching the section's own banner variable).
- Recharge: `ELSEIF((NN.EQ.2.AND.FLWM(...).GT.0.0).OR.(NN.EQ.1.AND.FLWM(...).LT.0.0))THEN` (`:6535-6536`) -- one combined condition covering both sides (this branch tests `FLWM`, not `FLWHM`, matching a legacy authoring habit shared with the micropore section's own recharge test; `FLWM`/`FLWHM` sign agreement in practice is not verified this pass, but the *structural* combination of both `NN` cases into one condition is present and correct here).

**`trnsfrs.f`'s macropore boundary (`trnsfrs.f:8082-8415`), the salt-file instance of this same section, diverges from both of the above:**
- Discharge: `IF(NN.EQ.1.AND.FLWHM(M,N,M6,M5,M4).GT.0.0)THEN` (`:8092`) -- **covers only `NN.EQ.1`**. There is no `.OR.NN.EQ.2.AND.FLWHM(...).LT.0.0` clause, unlike both the micropore section immediately above it and the sibling gas file at the identical location.
- "Recharge (negative flux)": `ELSEIF(NN.EQ.1.AND.FLWM(M,N,M6,M5,M4).LT.0.0)THEN` (`:8161`) -- tests `FLWM` (micropore flux), restricted to `NN.EQ.1` only, using an `AMAX1(VFLW*donor_content, FLWHM*boundary_concentration)` ceiling form.
- "Recharge (positive flux)": `ELSEIF(NN.EQ.2.AND.FLWM(M,N,M6,M5,M4).GT.0.0)THEN` (`:8263`) -- tests `FLWM`, restricted to `NN.EQ.2` only, using the mirrored `AMIN1(...)` form.
- `ELSE` (`:8365`): all 48 salt/phosphate species zeroed.

Enumerating the four `(NN, sign-of-FLWHM)` combinations against these three branches: `NN=1,FLWHM>0` is discharge (branch 1, correct); `NN=1,FLWHM<0` falls to branch 2 only if `FLWM` also happens to be negative -- if `FLWM>=0` while `FLWHM<0` (micropore and macropore flow directions disagree, or micropore flow is exactly zero while macropore flow is negative), the `ELSE` fires and the macropore boundary recharge is silently zeroed even though `ABS(VFLW)>ZERO` (i.e., `FLWHM!=0`) already established that a nonzero macropore boundary flux exists. `NN=2,FLWHM<0` (the discharge mirror case, structurally identical to `trnsfr.f:6501`'s explicit `.OR.NN.EQ.2.AND.FLWHM(...).LT.0.0` clause) is **not handled by any discharge-labeled branch at all** in `trnsfrs.f`; it can only be captured by branch 3 (`NN=2,FLWM>0`), and only if `FLWM`'s sign happens to be positive while `FLWHM`'s sign is negative -- in which case a physical *discharge* event (macropore flow leaving the domain) is computed using the "recharge (positive)" `AMIN1(VFLW*donor_content, FLWHM*boundary_concentration)` formula (a boundary-concentration-based inflow formula) rather than the donor-content-only discharge formula used by branch 1. If `FLWM<=0` in that same case, the `ELSE` fires and the flux is zeroed instead.

## Pattern classification

This is not a re-occurrence of `issue-029`'s specific mechanism (conditional netting of a donor concentration against its own lateral exchange flux) -- it is a distinct instance of this project's broader recurring theme (directional/branch-coverage asymmetry between physically-mirrored cases), here compounded by a variable-substitution inconsistency (`FLWM` used as the direction gate in a section whose own banner, discharge branch, and formula bodies are all keyed on `FLWHM`). The clean three-way contrast -- micropore section (symmetric, correct variable), sibling gas macropore section (symmetric discharge branch, same `FLWM`-in-recharge habit), salt macropore section (asymmetric discharge branch, `FLWM`-in-recharge habit) -- isolates the defect to `trnsfrs.f`'s discharge-branch condition specifically (missing `.OR.NN.EQ.2.AND.FLWHM(...).LT.0.0`), not to the shared `FLWM`-recharge-gate convention (which both sibling files use identically and is therefore likely an intentional/legacy convention, not itself a translation defect).

## Zig counterpart search and finding

`ecosys-ng/src/soil/solute/external_boundaries.zig`'s `calculateNetFluxMol` (`:20-51`) implements this section generically and **direction-independently**: it branches purely on the sign of `boundary.outward_water_flux_m3_per_step` (positive = discharge, negative = recharge), with no `NN`-style side/orientation parameter at all. The function's own doc comment (`:10-19`) already documents and deliberately reproduces the *micropore-vs-macropore* asymmetry within `trnsfrs.f` (unconditional micropore recharge vs. donor-content-ceiling-capped macropore recharge, citing `trnsfrs.f:7825-7892` and `:8161-8163,8263-8265`), via the `apply_donor_content_ceiling` parameter -- but that citation only reaches the *formula* used inside the recharge branches, not the *branch-selection* logic (which `NN`/sign combination reaches which formula) documented above.

Because Zig's function decides discharge-vs-recharge purely from the flux's own sign, it cannot structurally reproduce either (a) the missing discharge coverage for the `NN=2,FLWHM<0` case, or (b) the `FLWM`-vs-`FLWHM` variable substitution in the recharge gate -- every macropore boundary face reaching this function is classified correctly by its own `FLWHM` sign regardless of `NN`, and unconditionally gets the ceiling-capped recharge formula when inbound. This means Zig's macropore boundary treatment at this exact site is **more permissive/complete than the legacy `trnsfrs.f` source**: cases where the legacy code would zero the flux (or misapply the wrong formula) due to the `FLWM`/`FLWHM` disagreement or the missing `NN=2` discharge clause are, in Zig, always computed via the physically-appropriate discharge or recharge formula based on the macropore flux's actual sign. No documented review or feature entry was found approving this as an intentional correction; `driver/transport_step.zig`'s `advanceSoilSolutes` (`:405-419`) wires the boundary and pore-exchange calls generically with no citation of this specific branch-structure difference.

## Disposition: `unresolved`

The legacy branch structure at `trnsfrs.f:8082-8415` is confirmed to diverge, in a reviewer-relevant way, from both the symmetric micropore section immediately above it and the sibling gas file's structurally-equivalent macropore section. Whether the resulting legacy behavior (occasional zeroed or misclassified macropore boundary flux at lateral domain edges, when `FLWM` and `FLWHM` disagree in sign) is a genuine unintended defect that Zig's uniform, sign-based treatment silently and correctly avoids (candidate `legacy-defect-corrected`), or whether there is a physical reason the legacy code deliberately gates macropore boundary recharge on the *micropore* flux's sign that this pass did not uncover (in which case Zig's divergence from that specific gating would need its own review), requires a reviewer's physical judgment rather than an autonomous conclusion. Per contract this cannot be marked `preserved` (Zig does not reproduce the branch structure) or `legacy-defect-corrected` (no recorded review) without that review.
