Failure signature and first bad time/location/process:
Legacy `f77src/starte.f` lines 178-191 (`STARTE`, block `K.EQ.3.AND.I.EQ.1`, "INITIALIZE IONS IN SOIL WATER N") derives initial soluble ion concentrations from the soil file's saturated-paste-extract values:
```
189   CN4X=0.1*CNH4(L,NY,NX)
190   CNOX=CNO3(L,NY,NX)
191   CPOX=0.01*CPO4(L,NY,NX)
```
(comment block lines 167-168: `C*=soluble concentration from sat. paste extract in soil file NH4,NO3,PO4=NH4-N,NO3-N,H2PO4-P (mol Mg-1)`). These two multipliers (`0.1` for ammonium, `0.01` for phosphate) are hardcoded literals in the oracle, with no input-file override mechanism visible in this block.

The Zig translation makes both multipliers runtime-configurable via the runscript's `chemistry_units` record (`src/driver/runscript.zig:404` `saturated_paste_phosphate_multiplier`, `:436` `soil_ammonium_extract_multiplier`, both validated `> 1` as a hard ceiling, consumed in `src/soil/chemistry/initialization.zig:513`/`:517` and `:550`/`:563` respectively). The **phosphate** multiplier's configured value for the Ottawa deck matches the oracle exactly: `ecosys-ng-prod-examples/Cool Temperate Maize-Soybean ON/runottawa` line 76, `chemistry_units,14,31,27,56,40,24.3,23,39.1,32,35.5,1,1,0.01,1` -- decoding this record against `runscript.zig`'s field order (10 molar masses, then `minimum_ammonium_g_n_per_megagram=1`, `minimum_calcium_g_per_megagram=1`, `soil_ammonium_extract_multiplier=0.01`, `extract_mol_per_megagram_to_mol_per_m3=1`) gives **`soil_ammonium_extract_multiplier = 0.01`**, i.e. **10x smaller than the oracle's hardcoded `0.1`**. (The separate `saturated_paste_phosphate_multiplier`, from the earlier `chemistry_initialization` record, is `0.01` and matches `CPOX`'s `0.01` exactly -- confirmed correct, not part of this issue.)

Scientific/output impact: NOT YET MEASURED. If confirmed, every soil layer's initial soluble ammonium concentration derived from the saturated-paste-extract soil-file value would be seeded at 1/10th of the legacy oracle's value at simulation start, a systematic low bias in initial plant-available nitrogen for the entire Ottawa run. This is a DIFFERENT initial-ammonium concern from the already-tracked `INIT-007` (a 437x clamp discrepancy in `derivation.zig:97`'s `@max(1.0, supplied)` floor, per `docs/traceability/initial_inventory_comparison.md` -- not yet reconciled with this finding; they may compound, partially cancel, or affect different code paths (a hard floor vs. a paste-extract multiplier) and should not be assumed related without checking whether `derivation.zig`'s consumer is even downstream of this multiplier).

## Resolution
Cause and focused patch: corrected the shipped `chemistry_units` record's ammonium-extract-multiplier field from `0.01` to `0.1` in both `ecosys-ng-prod-examples/Cool Temperate Maize-Soybean ON/runottawa` (the production deck) and `ecosys-ng/src/validation/testdata/ottawa/runottawa` (the byte-identical test fixture, per its own stated invariant), keeping them byte-identical (verified: both now 9,795 bytes, SHA-256 `7ed4b809b654cb2e1dc6919c8d7e0e5608b81a2e4ad0950bdf23f5b613ae6409`). Updated `testdata/ottawa/PROVENANCE.json`'s `runottawa` entry to the new byte count/hash so the existing `required Ottawa inputs match immutable byte provenance` test continues to enforce integrity rather than silently going stale.
Before/after results: before, the shipped record parsed to `soil_ammonium_extract_multiplier = 0.01` (10x below the `starte.f:189` oracle value `0.1`); after, it parses to `0.1`, matching the oracle exactly. The sibling `saturated_paste_phosphate_multiplier` was already correct (`0.01`, matching `starte.f:191`) and is unchanged.
Regression added and actually executed: new test `"the shipped runscript's chemistry multipliers match the STARTE oracle"` in `ecosys-ng/src/validation/production_input_layout_test.zig`, parsing the real shipped runscript and pinning both multipliers against their distinct oracle-cited values (`starte.f:189`/`:191`) so a future edit cannot silently reintroduce the mismatch or transpose the two constants. Ran via direct `zig test src/module_index.zig --test-filter` (bypassing the currently slow/unreliable `zig build test` path): this new test passes, the pre-existing byte-provenance test still passes after the `PROVENANCE.json` update, and all 52 tests in that compilation unit pass with zero failures.
Invalidated evidence and rerun dependencies: any future full-deck run using the old `runottawa` (0.01 ammonium multiplier) predates this fix and should not be compared numerically against a post-fix run without noting the input changed. No prior full production run is known to have used the corrected value.
