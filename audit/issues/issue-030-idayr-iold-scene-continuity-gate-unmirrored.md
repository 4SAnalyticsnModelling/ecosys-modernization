## Confirmed content and location

Legacy: `exec.f:94-99` sets, unconditionally, every simulated day: `IDAYR = (IDAYR.LT.0) ? LYRX+IDAYR : I` and `IOLD = I`. `soil.f:285-289` (immediately after `CALL EXEC(I)`, `soil.f:278`) tests `IF(NYR.NE.1.AND.IDAYR.NE.IOLD)` to decide whether to re-read state from checkpoint (`CALL ROUTS`/`CALL ROUTP`). The same `IDAYR.NE.IOLD` comparison also gates full cold-start re-initialization at the top of a new scene: `soil.f:39` (`STARTS`), `soil.f:78` (`STARTQ`), `soil.f:106` (`STARTE`), each as `IF((DATA(20).EQ.'YES'.AND.IGO.EQ.0).OR.IDAYR.NE.IOLD)THEN`.

`reads.f` is called once per scene (`soil.f:32`, before the day loop) and sets the scene-boundary sentinel that this comparison actually tests against: `reads.f:760` `IDAYR=MIN(ISTART-1,ILAST)` with `NYR=0` for a mid-year scene end, or (`reads.f:763-767`) `IDAYR=LYRX` (`LYRX`=days in the previous year) with `NYR=1` and `IYRR=IDATA(3)-1` for a year-boundary scene end. Because `exec.f` re-syncs `IDAYR=IOLD=I` every day *during* the day loop, `IDAYR` only ever differs from `IOLD` right after a fresh `reads.f` call at a new scene's start -- i.e. this is the mechanism by which a multi-scene deck can tell "this new scene picks up exactly where the last one's `exec.f` calls left off" (skip re-init, preserve continuous state) from "this new scene is discontinuous" (force re-init via `STARTS`/`STARTQ`/`STARTE`, or force a checkpoint reload via `ROUTS`/`ROUTP`).

**Zig's own code explicitly documents the absence of an equivalent gate.** `ecosys-ng/src/ecosys_ng.zig:312-316`, inside `recordHourStageExecution` (a stage-execution census/measurement instrument, not a science-path branch):

> "The day-of-year wrap. The deck is six forcing years repeated five times with continuous state, so this fires at each 365->1 boundary. Legacy handles that boundary with `reads.f:760-767` setting IDAYR=365 so `soil.f:39,78,106` do not re-initialize; ng has no such gate, so whether this ever fires is exactly what needs measuring."

This is a same-repository, in-code admission that (a) the production deck this project validates against exercises exactly the multi-scene-repeat pattern this gate exists for, (b) legacy's behavior at that boundary is to *suppress* re-initialization via the `IDAYR`/`IOLD` mechanism, and (c) ng has not confirmed it reproduces that suppression -- only that it *measures* whether the boundary is crossed (`census.record(.day_of_year_reset, hour)`, `:319`), not that it takes the corresponding action.

## Why this matters

If ng's production driver re-initializes (or fails to re-initialize) state at scene/year boundaries differently from legacy's `IDAYR.NE.IOLD`-gated behavior, this would be a **state-continuity divergence at exactly the boundaries a multi-year-repeat production deck crosses** -- silently re-zeroing accumulators that legacy carries forward, or vice versa, carrying forward state that legacy intentionally resets. This is not a numerical-precision or translation-defect question in the usual sense (an equation mismatch); it is a control-flow question about *whether the same reset/carry-forward decision is made at all*, which the contract's investigation order places above physics-level attribution ("Investigate differences in this order: unequal inputs/initialization; parsing or output semantics; missing/incorrect bindings and update order... **then** approved physical changes"). A silent divergence here could manifest as an unexplained mass-balance or state discontinuity at scene boundaries in exactly the kind of multi-scene comparison run this project's output-comparison work depends on (`feature-019`), and could masquerade as a physics or precision bug if not checked first at this control-flow level.

## Trace findings (2026-09-19)

Bounded, read-only static trace covering "Next bounded action" items 1 and 2 only (items 3 and 4 are out of this pass's scope: item 3 needs a human design decision, item 4 needs an independent review). No source was modified; no model run was executed.

**1. Every scene-boundary code path in `ecosys_ng.zig`, traced.**

The scene/pass loop lives in the function containing `TimelineState` (`ecosys_ng.zig:268-282`, `~7900-8085`). At each scene start (`scene_weather_hours == 0`, `:7948`), exactly one conditional action fires:

- `shouldSeedStarteChemistryAtSceneStart(executed_scene_passes)` (`:276-278`, called at `:7949`) returns `executed_scene_passes == 0` -- true only before the very first scene pass of the *entire run*, false for every subsequent scene, unconditionally, regardless of whether that scene's boundary is continuous or discontinuous relative to the one before it. When true, it seeds gas-transport dissolved CO2 and micropore solutes from STARTE-equilibrated chemistry (`:7956-7970`) -- this is the closest analog to legacy's `STARTE` gas seeding (`soil.f:106`). The governing comment at `:7945-7947` and `:7950-7955` states the design intent explicitly: "Later scenes inherit the live authoritative transport owners. Reapplying this seed at every scene boundary overwrites evolved dissolved CO2 and creates an unbooked carbon source." This is a first-pass-only seed, not a discontinuity-keyed gate.
- The landscape mass-balance monitor is either freshly initialized (`:7985-7993`, only when `scene_weather_hours == 0`) or, for a resumed scene, required to already exist (`:7994-7995`) -- again keyed off scene-start-vs-mid-scene, not off discontinuity detection.
- `recordHourStageExecution` (`:299-322`, called at `:8044`) only records `.day_of_year_reset` into the census; it takes no other action, confirming the issue's original finding.
- At scene-pass completion, `.scene_transition` and (for `executed_scene_passes > 1`) `.forcing_repeat_transition` are recorded into the census (`:8077-8080`) -- again census-only, no state action.

No other conditional branch in the scene-start or scene-end code paths tests anything resembling `IDAYR.NE.IOLD` (a continuity/discontinuity comparison). **Confirmed: no code takes a `STARTS`/`STARTQ`/`STARTE`- or `ROUTS`/`ROUTP`-equivalent action keyed off detecting a scene/year-boundary discontinuity, separate from census recording.** The one scene-start conditional action that exists (`shouldSeedStarteChemistryAtSceneStart`) is keyed off absolute pass count, not discontinuity.

**2. `checkpoint_resume.validateCompletedDayBoundary`/`validatePlantMetadata` and `resume_from_checkpoint`, checked explicitly.**

- `options.zig:49` declares `resume_from_checkpoint: bool` as a per-scene field; `options.zig:99` parses it from a `YES`/`NO` runscript record (`parseSingleYesNo`). This is an explicit, human-authored request per scene, not a runtime-computed discontinuity test.
- `ecosys_ng.zig:492`: `if (driver_context.scene_options.*[first_requested_pass.scene_index].resume_from_checkpoint) { ... }` -- the entire checkpoint-bundle-read/reload/`validateCompletedDayBoundary`(`:519`)/`validatePlantMetadata`(`:553`) block is gated solely on this explicit flag being `YES` for the scene about to run. It never fires automatically from a day-of-year 365->1 detection.
- `checkpoint_resume.zig:15-24`'s own header comment states plainly: "no example resumes from a checkpoint, so the gate cannot exercise the binding" -- i.e., this reload path is currently untested in production, not just unautomated.
- Confirmed directly against the actual production deck: `ecosys-ng-prod-examples/Cool Temperate Maize-Soybean ON/runottawa` (lines 89, 103, 117, 131-132, 145, 159) sets `resume_from_checkpoint=NO` for every one of its six scenes (1998-2003), each repeated 5 times (`runottawa:3`, `1,1,5`). The reload half is present as a manual-only mechanism and is not exercised at all by this project's validated deck.

**Conclusion for items 1 and 2**: the *reload* half (`ROUTS`/`ROUTP`-equivalent) exists only as an explicit, human-requested, currently-unused-in-production mechanism -- it is not the automatic discontinuity-keyed gate legacy has. The *cold-start-suppression* half (`STARTS`/`STARTQ`/`STARTE`-equivalent) has no discontinuity-keyed analog anywhere; the one related mechanism found (`shouldSeedStarteChemistryAtSceneStart`) is keyed off absolute first-pass status, not discontinuity, and is explicitly designed to suppress re-seeding at every later scene boundary unconditionally -- which happens to match legacy's *continuous* case for this deck (since Ottawa's repeat-scenes are meant to chain continuously) but is not derived from or contingent on any continuity check, and would not distinguish a genuinely discontinuous scene (if one existed) from a continuous one.
