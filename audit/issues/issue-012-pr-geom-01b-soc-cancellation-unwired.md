## Resolved (2026-09-18, same session): CONFIRMED real and open, but currently LATENT -- registered elsewhere as `GEOM-SUBSIDENCE-001`

Checked for the HOUR1-002/SOLUTE-042 false-alarm pattern first, per this session's standing lesson. This one does NOT resolve that way -- it is genuinely open, and turns out to already have a much more thorough writeup elsewhere in the tree than the `PR-GEOM-01B` tag alone suggested.

**Full mechanism, traced end to end:**
1. `ecosys-ng/src/redistribution/erosion/organic_matter_apply.zig:1-55` (header comment) is an exceptionally thorough self-audit already in the codebase, registering this as **`GEOM-SUBSIDENCE-001`** (cross-referenced to `docs/traceability/geometry_subsidence_erosion_and_soc_datum_legs_are_dead.md` -- not present in this `D:` checkout, consistent with issue-005's established missing-`docs/` pattern; check the OneDrive reference for it before re-deriving).
2. Legacy policy (verified by that comment against `redist.f:6871-6873,6870`): `DORGC(L)=ORGCX(L)-ORGC(L)-ORGCC(L)`, with `+DORGE` added for the surface layer only, inside `IF(IERSNG.EQ.2.OR.IERSNG.EQ.3)`. Since `ORGCX` is the pre-change snapshot, this addition **cancels eroded (sediment-transported) carbon out of the subsidence driver** -- only biologically-driven carbon change may move a layer boundary; sediment-transported carbon is already accounted for by the erosion datum shift.
3. Production's actual publisher, `soil/organic/carbon_change.zig`'s `publishAcceptedHourlyChange`, forms a **plain hour-start-minus-current difference with no `+DORGE` term at all** -- i.e. the value that reaches `hourly_geometry_disturbance.zig:302`'s `context.soil_organic_carbon_change_g_c_per_h`, and from there `geometry_disturbance_transaction.zig`'s `organic_carbon_change_after_erosion_cancellation_g_c` field, is genuinely the **uncancelled** difference the field's own name and comment warn against -- confirmed by reading the actual call chain (`ecosys_ng.zig:9585,9677-9682,12282,13748` -> `hourly_geometry_disturbance.zig:191,302`), not just the comment.
4. **Why this is not observable today**: `soil/profile/relayering.zig:73-75` allocates the workspace's `organic_carbon` (SOC boundary-change) buffer and `@memset`s it to zero, and (per `organic_matter_apply.zig:38-39`'s own claim, consistent with what I read) it is never subsequently overwritten with the real per-hour value in production -- i.e. a *separate*, independent hard-wired-zero currently overrides whatever the uncancelled/miscancelled value would have been, before it can move a layer boundary. The bug is real and wired-in, but its effect is currently masked by an unrelated zero-override downstream.

**This is the opposite failure mode from HOUR1-002/SOLUTE-042**: those were cases where a stale comment claimed a bug that the actual (correct) production code had already fixed. This is a case where the code comment's warning is accurate and the bug is real, but a *different* zero-override happens to prevent it from causing observable divergence *today*. **It would become a live, observable defect the moment anyone wires the SOC/erosion boundary-datum legs to a real nonzero value without also porting the `+DORGE` cancellation.**

**Disposition: `unresolved`, confirmed OPEN.** Genuinely blocks nothing today (latent), but is exactly the kind of "trap for the next reader" the in-code comment itself warns about, and is relevant to "no science gaps" as a known, documented, currently-inert defect that must be fixed together with whoever eventually wires the SOC/erosion legs -- not fixed in isolation (the comment explicitly warns `DORGE` must be re-derived together with its reset in `redistribution/ecosystem/call_initialization.zig`, not lifted from either file alone).

## Closing review (2026-09-19)

Independent re-derivation from scratch (source-embedded `PR-GEOM-01B` tag treated only as a lead, not as evidence), per this session's closing-review pass.

**Finding: the 2026-09-18 filing's central premise -- "no `+DORGE`-equivalent producer exists in production" -- is false.** It is the same false-alarm shape as `issue-010`/HOUR1-002, just one hop further away than the filer's own check covered.

1. **Traced the actual consumer.** `ecosys-ng/src/soil/organic/carbon_change.zig`'s `publishAcceptedHourlyChange` (`:11-38`) does **not** form "a plain hour-start-minus-current difference with no `+DORGE` term at all," contrary to both the 2026-09-18 filing and `organic_matter_apply.zig`'s own header comment. It computes `hour_start_carbon_g_c[layer] - final_carbon_g_c + erosion_change_g_c`, where `erosion_change_g_c` is the caller-supplied `accepted_erosion_carbon_net_change_g_c[layer]` -- exactly `redist.f:6871-6873`'s `DORGC = ORGCX - ORGC - ORGCC` plus `+DORGE`. Its own test, `"REDIST DORGE cancels accepted erosion carbon and retains biological loss"` (`:65-83`), proves the cancellation numerically: 10 g eroded + 5 g biological loss nets to `change[0] = 5` (erosion cancelled, only biological change counted); a pure 10 g deposition nets to `0`.
2. **Traced the real producer of that erosion term.** `ecosys.soil_organic_carbon_change_g_c_per_h`'s `accepted_erosion_carbon_net_change_g_c` argument is `context.erosion_organic_carbon_net_change_g_c`, published every hour by `ecosys-ng/src/soil/profile/erosion_organic_bridge.zig`'s `publishLocalCarbonNetChangeMapped` (`:210-255`), called from production at `ecosys-ng/src/stages/hourly_sediment.zig:221-227` with the real per-hour eroded-organic workspace (`context.eroded_organic_workspace.pools`) and the real per-cell surface layer index (`context.erosion_topsoil_layer_by_cell`). This function's own doc comment (`:191-194`, `:257-259`) and its sibling `publishAcceptedCarbonNetChange` (`:49-52`, "Publishes legacy DORGE from the accepted directional fluxes themselves... exactly matching REDIST's `IF(L.EQ.NU) DORGC=DORGC+DORGE` branch") both explicitly self-identify as the DORGE producer, and both correctly restrict the write to each cell's current surface layer (`local`/`top_layer_by_cell`), matching legacy's `L.EQ.NU` scoping exactly.
3. **The order is correct.** `hourly_vegetation.zig`'s `finalizeRedistAndLedgers` calls `publishAcceptedHourlyChange` (`:473-478`) immediately after the comment "EROSION and every transport owner have completed before this function is entered" (`:459-461`) -- i.e. the erosion-carbon term is guaranteed fresh before the cancellation formula consumes it, every hour.
4. **Re-ran the grep the 2026-09-18 filing and `organic_matter_apply.zig` both relied on.** `organic_matter_apply.zig:29` asserts "a case-insensitive grep for `dorge` across `src` returns only this module and commentary in `redistribution/ecosystem/call_initialization.zig`." An actual case-insensitive grep for `dorge` across `ecosys-ng/src` (run this session) also returns `erosion_organic_bridge.zig` (5 hits, including two explicit "DORGE" doc comments) and `carbon_change.zig` (3 hits, including the exact `redist.f:6871-6873` citation and the cancellation test name). The claim in `organic_matter_apply.zig` is itself stale/wrong, not just incomplete.
5. **Found the documentation trail explaining the drift.** `redistribution/ecosystem/call_initialization.zig`'s own top banner (`:1-4`, apparently added after the paragraph it precedes) already states: "Current production reconstructs the DORGE-equivalent accepted hourly organic change before the bound geometry/erosion transaction... The detailed text below is the retained historical audit and its former GAP conclusion is superseded." The retained historical text below it (`:32-39`) is the same stale "no DORGE accumulator" claim that `organic_matter_apply.zig` and the 2026-09-18 filing both repeat. `organic_matter_apply.zig` and the `PR-GEOM-01B` tag in `geometry_disturbance_transaction.zig:112-114` were never given the same superseding correction -- they are the stale siblings of an already-corrected finding elsewhere in the same audit family (`docs/traceability/redistribution_erosion_apply_family_disposition.md`, not present in this checkout).
6. **The one part of the 2026-09-18 filing that is real and worth keeping**: `soil/profile/erosion/organic_matter_apply.zig`'s own `apply` kernel (the one the old `TRC-032` row cited) genuinely is dead/unbound -- it is a superseded standalone DORGE-computation kernel with no caller, correctly identified as such by that module's own family argument. It is simply not the producer production actually uses; production's real producer (`erosion_organic_bridge.zig`) is a different, live module that happens to implement the same legacy formula correctly.
7. **Materiality, for completeness (not load-bearing for this disposition):** the Ottawa deck's `f25si98` record 3 does select `erosion_mode = 3` (confirmed by direct read), which would make both the erosion and SOC legs of the geometry transaction reachable if this had been a real gap. It is not a gap, so this does not change any current production output -- noted only because it means the original filing's "currently latent, blocks nothing" fallback conclusion was also independently wrong on its own terms (the mode-gate claim and the `relayering.zig:73-75` "hard-wired zero override" claim conflate an unrelated field, `organic_carbon_g_per_megagram` -- a per-hour-refreshed density used only for the organic-horizon-threshold check -- with the actual boundary-change buffer, which is not held at zero for this deck).
