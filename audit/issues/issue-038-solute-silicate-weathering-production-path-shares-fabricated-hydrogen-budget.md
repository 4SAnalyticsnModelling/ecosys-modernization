# Issue 038 -- SOLUTE.F silicate weathering: the production Zig path shares an undocumented hydrogen budget between natural and ground rock dissolution that the Fortran does not have; the faithful translation exists only in a self-test

Status: **OPEN, needs a coordinator/reviewer scope decision.** Not a sign error or a translation-order mistake; it is an added physical constraint with no legacy counterpart, currently exercised in production without appearing in the feature register.

Owner: found by this session's audit fork, 2026-09-19, while auditing FEAT-017's "silicate weathering equations" assignment (`f77src/solute.f`).

## What was found

`f77src/solute.f:1895-1971` computes six cations' (Al, Fe, Ca, Mg, Na, K) natural-rock (`RQ*SI`) and ground-rock (`RQ*SIF`) silicate dissolution rates. Each of the twelve rates is clipped independently by `AMIN1(0.0,AMAX1(-Q*SI1,-TRWXA,(AMIN1(TRWXA,(A*1-A*Q)))))` (natural) or the `TRWXF`/`Q*SIF1` analogue (ground) -- i.e. each rate is bounded only by (a) its own available rock inventory, (b) its own species' maximum-rate constant (`TRWXA`/`TRWXF`, both derived from a shared `TFNW`/`SSA`/`SSAF` but with no cross-species or cross-natural/ground coupling), and (c) the same thermodynamic driving force `(activity - equilibrium activity)`. There is **no** hydrogen-ion-availability term anywhere in this clipping. The closure at `:2388-2391` (`CHYSI1` update) and the aggregate ion mass balance at `:2168-2192` (`RHY=RZHYS+3.0*(RQALSI+RQALSIF+RQFESI+RQFESIF)+...`) fold the H+ consumption in *after* the twelve rates are already fixed; the reaction network's global H+ balance is enforced by the outer Newton/Anderson iteration (already covered by `feature-003`) operating over many small (`TRWXH/MRXN`) substeps, not by a local per-mineral H+ cap.

`ecosys-ng/src/soil/solute/silicate_weathering.zig` (sha256 `998DEB4AEEC0FEC63781ADADD006CB26D9B645A03B5C77E51EF727620CB4922D`) implements **two** functions:
- `calculateSourceOrder` (`:52-99`): faithfully mirrors the Fortran -- natural and ground extents each independently clipped against the same driving force, no shared budget. Doc comment: "the source does not share an aqueous-hydrogen budget between them." A dedicated test (`"source-order natural and ground weathering have independent limits"`, `:228-264`) proves this against a hand-computed source-order expectation.
- `calculate` (`:22-47`, the *default*, undecorated name): computes an additional `hydrogen_limit = state.hydrogen_mol_per_m3 / charge` not present anywhere in the Fortran, clips the natural extent to it, then clips the ground extent to `remaining_hydrogen_extent = hydrogen_limit - natural_extent` -- i.e. natural and ground dissolution of the **same mineral species** are made to compete for one shared local H+ budget within a single call. The same test file's own comparison test (`:228-264`) demonstrates the two functions diverge under low-hydrogen conditions (conservative: natural=0.001, ground=0; source-order: natural=0.12, ground=0.08, both capped only by their own maxima).

`ecosys-ng/src/soil/solute/geochemistry_reaction_rates.zig` (sha256 `3A26CBAAFBE243F69CD755901DBE6AE8053043E210109C3AB8FD6D64A7F365C9`), the production entry point (`calculate`, `:49-90`), calls `weather()` (`:181-183`) for all six cations, and `weather()` calls `silicate_weathering.calculate` -- the modified-physics version, **not** `calculateSourceOrder`. A whole-tree grep for `calculateSourceOrder` inside `silicate_weathering.zig`'s own namespace (`grep -rn "calculateSourceOrder" ecosys-ng/src`) shows its only caller is the file's own comparison test (`:241`); it has no production caller.

This is the mirror image of `issue-037`'s pattern: there, the faithful restricted-domain translation is unwired and only the full-salt formula runs in production (source-faithful, but the wrong branch reachable). Here, the faithful **source-order** translation is unwired, and the **modified-physics** variant is what actually runs in production, with no feature-register entry, approval record, or `FEAT-0NN` citation documenting the change.

## Why this needs a record

Per the project contract, an intentional physical difference "require[s] individual entries in the feature register," and differences must first be investigated as translation/units/indexing defects before being accepted as approved physical changes. This deviation:
- Is systematic across all twelve rate expressions (all six cations, both natural and ground), not an isolated outlier -- every call to `weather()` in production goes through the modified path.
- Has no comment claiming a scientific justification beyond generic defensive-programming language ("avoid manufacturing infinity ... all following bounds remain finite and conservative") that describes the divide-by-zero guard, not the H+-budget-sharing itself.
- Was not disclosed in any prior FEAT-017 pass despite `silicate_weathering.zig`'s own doc comment citing `SOLUTE.F lines 1895--1937` as its translation target -- the citation reads as a faithfulness claim.
- Materiality is plausibly small in most cells (natural/ground silicate weathering rates are governed by a very small hourly rate constant, `TRWH=5.0E-05` divided by `MRXN=60` substeps, per `solute.f:118`), but the divergence test itself shows large fractional differences (natural 0.001 vs 0.12; ground 0 vs 0.08) once the local H+ pool is small relative to the uncapped thermodynamic driving force -- exactly the acidic/depleted-soil conditions where this process is scientifically most relevant.

## Disposition

`unresolved`, pending a coordinator/reviewer decision: either (a) the shared-hydrogen-budget behavior is an intentional, approved robustness improvement (e.g., to prevent within-step H+ depletion below zero when a soil cell has very little buffering capacity) -- in which case it needs its own `FEAT-0NN` entry, an explicit approval record, and a decision on whether it should also be applied to the mineral precipitation/dissolution kinetics (`feature-008`) which appear to use a similar `sourceClippedExtent`-vs-modified split pattern; or (b) it is an unintended deviation and production should call `calculateSourceOrder` (or `calculate` should be corrected to match source order) the same way `cation_exchange.zig`'s `calculateSourceOrder` is the actual production path elsewhere in this same file family. No production run this pass exercises a low-hydrogen soil cell to observe actual numerical impact; materiality beyond the unit test's synthetic inputs is not evaluated.
