### Where `RelayeringActivityConservationFailure` comes from

`ecosys-ng/src/soil/profile/relayering_activity.zig`'s `Sidecar.stageBoundary` (lines 168-235) checks, for one REDIST-ordered internal soil-layer boundary, that the donor layer's loss and the recipient layer's gain agree (within an absolute+relative+ULP tolerance) independently for every `inventory.Storage` field, including `heat_megajoules` (the sole signed field, lines 210-222). If `@abs(raw_loss - raw_gain) > allowed` for `heat_megajoules`, it returns `error.RelayeringActivityConservationFailure` (line 214). This check is structurally independent of, and does not call, `aqueousCarrierM3`/`legacyNegligibleWaterVolumeM3` or any of issue-060/061's fixed call sites -- it captures donor/recipient `inventory.Storage` snapshots directly via an injected `SnapshotSource` (lines 7-31), before/after a single boundary transfer.

**Working hypothesis (not yet confirmed by a targeted experiment): the ~14.7 MJ of heat discarded by WATSUB 6907 at cell 0/layer 0 this same hour is exactly the kind of donor-side "loss" that has no matching recipient-side "gain" once a REDIST boundary touching layer 0 is staged this hour.** The discard's compensating offset (`negligible_capacity_unabsorbed_megajoules_by_layer`) appears (from the comment at `heat_step.zig:3361-3363`) to be plumbed only to the hourly-cell-conservation census that issue-060 diagnosed and issue-060/061's fix (indirectly, by removing a different fake-loss source from the same ledger family) helped keep passing -- there is no evidence in this pass that the same offset is also supplied to `relayering_activity.zig`'s independent `SnapshotSource`-based before/after snapshots. If so, `stageBoundary`'s donor-side snapshot for layer 0 would show the discarded 14.7 MJ as a real loss with no corresponding recipient gain, tripping the `heat_megajoules` check. **This has not been confirmed by reading `SnapshotSource`'s actual capture function or by a targeted unit reproduction in this pass** -- flagged honestly as the first thing a follow-up pass should verify, not assumed here.
