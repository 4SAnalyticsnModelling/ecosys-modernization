## FINDING
DECISION: APPROVE decoupling `solute_reaction_max_iterations` and `initial_solute_reaction_max_iterations` from the deck cap `hard_max_iterations`. The reason is D6. The `@min(hard_max_iterations, …)` clamp (`iteration_control.zig:131-132`) is a Zig-only coupling with no legacy counterpart, because legacy reads no runtime field 6 (`reads.f:126`) and MRXN is a compile-time PARAMETER. T-00035 showed the reaction results depend on the ceiling (hour-9 divergence), so this clamp is an unjustified deviation. It is logged as DEV-007, REJECTED-REVERT.

The replacement semantics are:
1. Each field is a pure convergence ceiling, a fail-loud detector, and is not an MRXN equivalent. The values stay unchanged: SOLUTE 100 and STARTE 1000.
2. When the budget is exhausted, the solver must return `SoluteReactionSolverDidNotConverge` or escalate a substep. It must never commit truncated state.
3. The converged result must be ceiling-invariant.

This does not fix the hour-2,589 SOLUTE exhaustion. On the Ottawa deck the hourly SOLUTE ceiling is 100 both before and after, so decoupling it is a no-op there. That exhaustion stays a defect to root-cause (DEV-004 REJECTED-REVERT stands).

Legacy MRXN sub-cycling with per-cycle rates divided by MRXN is not reproduced by any Zig ceiling. I log that as an open science gap (G0-2b), not as approved.
