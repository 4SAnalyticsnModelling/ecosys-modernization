## FINDING
The Zig SOLUTE and STARTE budgets are convergence ceilings, not legacy fixed sub-cycle counts. In Zig, `hard_max_iterations` is applied with `@min(...)` to the solver limits and then consumed as `.max_iterations` by the reaction solvers (`ecosys-ng/src/core/iteration_control.zig:76-135`, `ecosys-ng/src/stages/soil_chemistry_convergence.zig:365-372`, `ecosys-ng/src/stages/hourly_process_driver.zig:634-670`), so they are runtime ceilings for Newton/Anderson iteration. In legacy Fortran, `MRXN` is a fixed loop count with rate constants pre-divided by `MRXN` (`f77src/solute.f:97-118`, `:368-375`, `:822`; `f77src/starte.f:101`, `:408`, `:1778`), so the divisor is the fixed sub-cycle count itself, not a convergence budget. The correct legacy semantics are therefore: legacy `MRXN` = fixed sub-cycle count / divisor for per-cycle rates, while Zig `*_max_iterations` = convergence ceiling.
