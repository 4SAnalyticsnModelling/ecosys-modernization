## FINDING
DECISION: the P0.4 legacy gfortran ×3 run is not launched inside any agent turn, and the FORGE budget stays at 60 minutes. Instead the controller launches it out of band as a supervised, non-agent job. The job holds `.agent/locks/machine.lock` for its whole duration. A FORGE task within budget then collects the results.
Why: T-00145 shows that a turn-bound launch fails (F-00009). A 600-minute agent turn still dies the same way if the wrapper kills it, and that kill orphans the lock. Neither option changes science, and the R5 rules (T-00142) already set the acceptance criteria. No second SAGE confirmation is needed.

Launch specification:
- L1. Run as the controller, outside any role pane:
  `uv run ecosys-audit/scripts/run_logged.py --cwd . --out audit/runs/p04-full-campaign --timeout 66000 -- uv run ecosys-audit/scripts/run_legacy_p04_full.py --runs 3 --timeout-per-run 21600 --campaign-id p04-full-<date> --out audit/runs/p04_full_run_receipt.json`
  The driver must match T-00146's sha256 `940D6B81…B8D8F1`. If the hash differs, do not launch.
- L2. Set the per-run timeout to 6 h, not the default 4 h. The only full-run timing evidence is run-002 at about 2h40m (`run-002…md:38`), and the 4 h default leaves only 1.5× headroom. T-00142 says the timeout must not be the stopping criterion; it is only a hang ceiling, so a timeout counts as a FAIL.
- L3. While the job runs, the swarm may run only tasks that need neither the machine lock nor a build: reading, SAGE, and PATHFINDER source work. The per-run system load must be recorded, because other activity perturbs the timing spread.
- L4. If the controller has no way to launch a non-agent job, SENTINEL routes a FORGE task instead (within budget, `ecosys-audit/scripts/` only). That task adds a detached mode to the driver: the child process holds the lock, writes a pid/heartbeat file, removes the lock on exit, and has a test for stale-lock recovery. The job is then launched through that mode.
- L5. Collection happens after the job exits, as a FORGE task of 60 minutes or less. It verifies the receipt against every R5 item, registers the output hashes, and hands over to SAGE for the conditions 3-4 review. `audit/output-provenance.csv` is not updated until that review passes.
