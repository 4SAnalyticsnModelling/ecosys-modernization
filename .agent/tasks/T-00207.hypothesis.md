# HYPOTHESIS: T-00207

## Observed defect
The legacy P0.4 Ottawa full-run driver (PID 41688) died without an exit receipt or traceback, while a stale RUN_FAILED receipt from an earlier run (01:15:58Z) remained on disk causing swarm confusion. Restaging run_1 silently wiped prior run logs without quarantine (preventing post-mortem diagnosis), and standard stdout buffering suppressed live child output until process exit.

## Evidence
- T-00206 PATHFINDER finding and evidence (`run_legacy_p04_full.py:518-545`, `driver.log`, `heartbeat.json`).
- T-00204 SAGE finding: stale `RUN_FAILED` receipt predates the 01:28:02Z lock; prior `run_1` logs overwritten on restage.
- `run_legacy_p04_full.py:637-640`: `stage_run_directory` calls `safe_rmtree` directly, deleting existing run artifacts.
- `run_legacy_p04_full.py:981-1021`: `--detach` spawns python without unbuffered stdout (`-u`), so short driver stdout buffers in userland and is lost on hard termination.
- Lack of an automated fresh terminal receipt validator that checks freshness against lock acquisition, exit code 0, determinism, and horizon completion.

## Proposed mechanism
1. Introduce quarantine logic (`quarantine_prior_run`, `quarantine_campaign_artifacts`) so that prior `run_1`, stale `driver.log`, and stale receipt files are preserved with timestamped quarantine names before any relaunch or restaging.
2. Harden the detached launch path with `--relaunch` and unbuffered execution (`sys.executable, "-u"`, `line_buffering=True`), teeing/logging stdout and stderr directly to a dedicated campaign log.
3. Maintain active machine lock and heartbeat daemon semantics (exclusive byte lock, dead PID / stale heartbeat recovery, live lock protection).
4. Implement `validate_terminal_receipt` checking receipt existence, freshness against minimum mtime / lock acquisition, status `ALL_RUNS_COMPLETED`, exit code 0 for all runs, horizon completion, and determinism across runs.

## Proposed change
- `ecosys-audit/scripts/run_legacy_p04_full.py`:
  - Add `quarantine_prior_run` and `quarantine_campaign_artifacts` functions.
  - Update `stage_run_directory` to quarantine existing directories rather than wiping them silently.
  - Harden `spawn_detached_child` and detached launch to pass `-u`, set line buffering on stdout, and redirect/tee output to campaign log.
  - Add `--relaunch` CLI mode and `--validate-receipt` CLI mode.
  - Implement `validate_terminal_receipt` function and CLI handler.
- `ecosys-audit/tests/test_run_legacy_p04_full.py`:
  - Add unit tests covering:
    - Quarantine of prior `run_1`, `driver.log`, and stale receipt.
    - Quarantine during restaging in `stage_run_directory`.
    - Hardened detached child launch with unbuffered logging.
    - Terminal receipt validation: rejecting stale receipts, rejecting failed runs, rejecting non-zero exit codes, rejecting missing horizon/determinism, and accepting valid fresh terminal receipts.

## Prediction
When the test suite `ecosys-audit/tests/test_run_legacy_p04_full.py` is executed, all new and existing tests pass:
- Quarantine moves prior `run_1` and stale artifacts to timestamped names without deleting them.
- `validate_terminal_receipt` returns `valid: False` on the stale `audit/runs/p04_full_run_receipt.json` (mtime < lock acquisition / status == RUN_FAILED), and `valid: True` only on a synthetic fresh valid receipt with exit code 0 and horizon check.
- Detached launch generates unbuffered campaign log output.

## Falsification condition
If quarantine fails to preserve prior directories, if `validate_terminal_receipt` accepts a stale or failed receipt, or if any existing lock/heartbeat tests fail, the hypothesis is falsified.
