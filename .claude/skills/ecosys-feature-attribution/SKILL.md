name: ecosys-feature-attribution
description: "Causally validate intentional physical/numerical changes; use when attributing differences to approved features."
---

Authority: `.agent/protocol.md`; read it once per session. Use `./scripts/project.sh pickup`
for current state and `exec` for logged heavy commands. One leader decides and verifies;
optional safe sub-agents follow the protocol. No adversarial reviewers or reviewer approval gates.

Record legacy and new equations/variant, interface units/state, source hashes and primary
references in a feature/DEV dossier. A feature name alone proves nothing.
From a reproduced discrepancy use matched states, isolated kernels, safe controlled variants
or limiting cases to identify cause; record confounders and interactions. Keep unchanged
interface tests separate from production-physics acceptance envelopes fixed before evaluation.
Show local correctness, downstream impact and independent conservation. If rules legitimately
change, validate held-out cases; never widen rules simply to encompass observed failure.
The model decides and records mechanism, numbers, affected outputs and retirement/equivalence.

For [numerical recovery](../../../.agent/playbooks/convergence-and-balance.md), show whether
changed scales affect only search or also accepted states. A legacy ZERO floor cannot justify
a new balance allowance without unit conversion and measured impact. Joint consumer limits,
phase treatment and temporary explicit subcycles require attributed science/output differences;
fewer iterations or legacy completion alone does not establish equivalence.
When legacy produces nonfinite or physically invalid finite values, retain the failing oracle
evidence, derive a valid modern behavior independently and attribute the repair. Do not copy
the defect, hide affected rows or claim scientific equivalence solely from later net balance.
Follow the [invalid-reference prerequisite](../../../ecosys-audit/qualification-evidence.md#invalid-legacy-reference):
a DEV does not bypass current F3 finite/direct-comparison checks. A proved reference defect
needs explicit validated evidence-contract support before affected qualification can pass.

For report/dependency schemas, readiness and suite accounting, use
[qualification evidence](../../../ecosys-audit/qualification-evidence.md) when recording or reusing verdicts.
