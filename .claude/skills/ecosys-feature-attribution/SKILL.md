---
name: ecosys-feature-attribution
description: "Causally validate intentional physical/numerical changes; use when attributing differences to approved features."
---

Authority: `.agent/protocol.md`; read it once per session. Use `./scripts/project.sh pickup`
for current state and `exec` for logged heavy commands. One model decides; no human approval.

Record legacy and new equations/variant, interface units/state, source hashes and primary
references in a feature/DEV dossier. A feature name alone proves nothing.
From a reproduced discrepancy use matched states, isolated kernels, safe controlled variants
or limiting cases to identify cause; record confounders and interactions. Keep unchanged
interface tests separate from production-physics acceptance envelopes fixed before evaluation.
Show local correctness, downstream impact and independent conservation. If rules legitimately
change, validate held-out cases; never widen rules simply to encompass observed failure.
The model decides and records mechanism, numbers, affected outputs and retirement/equivalence.

For report/dependency schemas, readiness and suite accounting, use
[qualification evidence](../../../ecosys-audit/qualification-evidence.md) when recording or reusing verdicts.
